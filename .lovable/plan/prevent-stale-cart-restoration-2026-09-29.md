# Prevent stale cart restoration

## Goal
Fix the two cart-sync races that can repopulate a deliberately cleared cart, without changing shopping controls or normal cart syncing.

## Changes
- Add an optional cart-clear timestamp to the saved browser lists and each customer's synced list record.
- Record that timestamp whenever the cart is cleared and persist it with the empty cart.
- Keep a newer deliberate local clear authoritative when an older synced cart is merged, while preserving today's merge behavior for existing records without timestamps.
- Cancel any pending delayed upload when another tab supplies newer cart state, preventing stale items from being written back.
- Leave the cart icon, mobile tab bar, cart actions, and normal sync delay unchanged.

## Verification
- Add a behavioral test proving a newer empty-cart clear cannot be overwritten by stale synced items.
- Retain coverage for the normal union and maximum-quantity merge behavior.
- Add a source-level regression check for cross-tab timer cancellation.
- Run focused cart/store tests, type checks, and verify the preview build.

## Technical scope
- `user_lists` receives one additive nullable timestamp column; existing list columns and rows remain compatible.
- Changes are limited to the shared cart state, store synchronization, database type update generated by the migration, and focused tests.
